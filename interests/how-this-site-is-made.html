How this site is built: a private Obsidian vault I write in, and a script that publishes only the notes I pick.

This whole site comes out of my notes. I write in Obsidian, a notes app that keeps everything as plain Markdown files in a folder. That folder is my "second brain": ideas, rabbit holes, recipes, photos, projects. Almost all of it is private. A few notes have one line at the top that says "publish this," and those become the pages you're reading.

The pieces

  • The vault. A folder of Markdown files, one note per topic. Interests, projects, recipes, photos and paintings each have their own folder.
  • A private GitHub repo. The vault lives in a private Git repository, so it's backed up and versioned, and every change has a history.
  • Sync. On my Linux desktop, the Obsidian Git plugin commits and pushes for me. On my Android phone, the GitSync app does the same job. I write on either one and the other catches up.
  • A build script. A small Python script reads the vault, picks out the notes marked to publish, and turns them into HTML pages: galleries, recipe tiles, the homepage sections and their order.
  • GitHub Actions. Every time the vault changes, a workflow runs the build script and pushes the finished pages to a separate public repo.
  • GitHub Pages. That public repo is served as this website. Free hosting, no server to run.

How a note gets published

  1. I write a note in Obsidian. By default it's private.
  2. When I want it public, I change one line in the note's frontmatter (the little block of settings at the top) to publish it.
  3. My phone or desktop syncs, the workflow runs, and about a minute later the page is live.

Photos work the same way: dropping a photo into the Photography or Paintings folder is the choice to publish it. The build strips camera and GPS data from every image before it goes up.

Even the homepage is notes. There's one note per section, and one note that sets their order, so I can rewrite a heading or reorder the page from my phone.

Keeping private things private

  • Nothing is public unless I mark it. The default is private.
  • Notes can be tagged so they never publish, even if I mark them by mistake.
  • Links to private notes just disappear from the public pages instead of leaking their titles.
  • Raw stuff like data exports stays in a folder that's never committed at all.

Claude as the librarian

Part of the vault borrows Andrej Karpathy's "LLM wiki" idea: I save articles and sources, and Claude (an AI assistant) reads them, writes and links summary notes, keeps an index and a log, and checks for contradictions. A map file at the top of the vault tells it where everything goes.

Mine is less of a research wiki and more of a messy personal one. The interest notes are mine: Claude can link them but doesn't rewrite them unless I ask. Ideas go into an inbox first and get sorted later. And unlike Karpathy's, mine has a public side, so the one rule Claude can't break is that it never publishes anything on its own. I pick every public note by hand.

If you want to build one

Copy this into an AI assistant that can work with files and GitHub (Claude Code works well), and it'll walk you through it:

Help me set up a "second brain" that also publishes a personal website.

- An Obsidian vault of plain Markdown notes, one topic per note, stored in a
  PRIVATE GitHub repo. Sync it on desktop with the Obsidian Git plugin and on
  my phone with a git app.
- A CLAUDE.md (or AGENTS.md) map at the top of the vault saying what each
  folder is for and what you may and may not edit.
- Every note has frontmatter with a publish field that defaults to false.
  You never change it yourself; I decide what goes public.
- A small Python build script that turns only published notes into a static
  site: a homepage built from section notes, interest pages, photo galleries
  (strip EXIF/GPS from every image) and recipe tiles. Links to private notes
  are removed, and a "private-only" tag blocks a note even if it's marked.
- A GitHub Actions workflow that runs the build on every push to the vault and
  pushes the result to a separate PUBLIC repo served by GitHub Pages, using a
  fine-grained token limited to that one repo.
- Optionally, Karpathy's LLM-wiki pattern: a read-only Sources/ folder, a
  Notes/ folder you maintain, index.md and log.md, and ingest / query / lint
  routines described in the map file.

Start small: make the vault and one note, then add publishing once I have
something worth publishing. Explain each step for a beginner, tell me exactly
what I need to click or run myself, and never put tokens in a file or chat.
